把 Nacos 3 接进 .NET
不该是一场翻译工作。

Lolitacoding.Nacos 是只面向 .NET 10 与 Nacos 3.x 的客户端 SDK： 配置中心、服务注册与发现、分布式锁、AI 注册中心，共用一条连接与一套选项。 它和 IConfiguration、依赖注入、HttpClient、Aspire 直接对齐，而不是各自为政。

01 — 特性

为什么再写一个 Nacos 客户端

把 Java 客户端逐行翻译过来，得到的只是一个能编译的 Java 程序。 这个库反过来：先问 .NET 里这件事本来该怎么做，再决定协议怎么落地。

01

只有 .NET 10

没有多目标框架，没有 netstandard 垫片。C# 14、System.Text.Json 源生成、Span<T>、Channel<T>、TimeProvider、IAsyncEnumerable 都直接用。

02

Native AOT 不是事后补的

没有反射序列化，没有运行时生成代码。仓库里每一个 IL2xxx / IL3xxx 都是错误，CI 每次都会真的发布一次 AOT 程序。

03

按 .NET 的形状设计

IConfiguration 提供程序、DI 单例、IHostedService、IHttpClientFactory、IOptionsMonitor 热更新——不是包一层，而是就是那个接口。

04

协议照上游，一个字都不猜

gRPC 走 Nacos 的私有协议，鉴权走 v3 HTTP OpenAPI。每个字段都在 docs/protocol-notes.md 里标了 Java 源码出处，https:// 即加密传输。

05

可观测性是一等公民

内置 ActivitySource 与 Meter，一行接进 OpenTelemetry，不必自己给 SDK 包埋点。

06

Aspire 里起一个 Nacos

AppHost 里 AddNacos("nacos") 拉容器、注入连接串，客户端用 AddNacosClient() 接上；本地开发不必先手动装一个服务端。

我们不做的三件事

  • 不兼容 Nacos 2.x。 3.x 的协议不一样，兼容只会让两套代码互相拖累。
  • 不多目标框架。 支持 netstandard2.0 意味着放弃 Span、Channel 和源生成。
  • 不用反射序列化。 它会让 AOT 和裁剪变成一句口号。

02 — 版本

你的服务端能提供什么

Nacos 3 的各模块不是同一批发布的。这张表是客户端判断能力的依据，也是 CI 里那三个镜像的来源。

03 — 代码

四个模块，一条连接

NacosClient 持有连接，Config、Naming、Lock、AI 是它的四个门面。连接按需打开，用完随客户端一起释放。 

// 读取；配置不存在不是错误，看 result.Exists。
var key = new NacosConfigKey("appsettings.json", NacosConstants.DefaultGroup);
NacosConfigResult result = await client.Config.GetConfigAsync(key);

// 发布。
await client.Config.PublishConfigAsync(
    key, """{"Logging":{"LogLevel":"Debug"}}""", contentType: "json");

// 监听变更。序列不会自己结束，除非取消令牌触发。
await foreach (NacosConfigChange change in client.Config.ListenAsync(key))
{
    Console.WriteLine($"{change.Key} (md5 {change.PreviousMd5}): {change.Content}");
}

// 按通配符跟随一组配置的成员变化，而不是某一个值。
await foreach (NacosConfigWatchEvent item in
    client.Config.WatchAsync("feature.*", NacosConstants.DefaultGroup))
{
    Console.WriteLine($"{item.Kind}: {item.Key}");
}
using Lolitacoding.Nacos.Naming;

var service = new NacosServiceKey("order-service", NacosConstants.DefaultGroup);

await client.Naming.RegisterInstanceAsync(
    service, new NacosInstance("10.0.0.5", 8080));

// 一条连接对一个服务只发布一组实例，所以多实例用批量接口。
await client.Naming.RegisterInstancesAsync(payment, [
    new NacosInstance("10.0.0.6", 8080),
    new NacosInstance("10.0.0.7", 8080),
]);

NacosServiceInfo info = await client.Naming.GetInstancesAsync(service);

// 只保留带标签的实例；过滤在客户端，订阅仍然只开一条。
var goldOnly = NacosInstanceSelectors.Metadata(
    new Dictionary<string, string> { ["tier"] = "gold" });

await foreach (NacosServiceChange change in
    client.Naming.SubscribeAsync(service, goldOnly))
{
    Console.WriteLine($"{change.Instances.Count} 个 gold 实例");
}
using Lolitacoding.Nacos.Locking;

NacosLock nightlyLock = client.Lock.GetLock(
    new NacosLockKey("nightly-reindex"),
    new NacosLockOptions { LeaseDuration = TimeSpan.FromSeconds(15) });

await using NacosLockLease lease = await nightlyLock.AcquireAsync(ct);

// …… 被保护的临界区 ……

// 没有 fencing token：锁随连接消失，提交前自己确认还握着。
if (!lease.IsHeld)
{
    // 这次执行的效果可能不再独占。
}
using Lolitacoding.Nacos.AI;

// MCP：服务器当前提供的工具、资源与端点。
NacosMcpServerDetail server = await client.AI.Mcp.GetServerAsync("weather", ct);

foreach (NacosMcpTool tool in server.ToolSpec?.Tools ?? [])
{
    Console.WriteLine(tool.Name);
}

// Nacos 没有 MCP 变更推送：订阅就是按间隔重读，变了才再报。
await foreach (NacosMcpServerDetail change in
    client.AI.Mcp.SubscribeServerAsync("weather", ct: ct))
{
    Console.WriteLine(change.VersionDetail?.Version);
}

// Prompt、Skill、Agent Spec、Agent Card，以及 3.3 的 RAD Agent watch。
NacosSkill skill = await client.AI.Skill.GetSkillAsync("release-notes", ct);
Console.WriteLine($"{skill.Version} ({skill.Md5}), {skill.Archive.Length} bytes");

04 — 包

七个包，按需取用

核心包不依赖任何 DI 容器；扩展包各自只做一件事，Aspire 的两个包把服务端和客户端连起来。

NuGet 包列表
包用途
Lolitacoding.Nacos核心 协议、传输、Config / Naming / Lock / AI 客户端。
Lolitacoding.Nacos.Extensions.DependencyInjection AddNacos(...)、选项绑定与校验、生命周期管理。
Lolitacoding.Nacos.Extensions.Configuration AddNacosConfiguration(...) 配置提供程序，带变更令牌与热更新。
Lolitacoding.Nacos.Extensions.ServiceDiscovery 接进 Microsoft.Extensions.ServiceDiscovery，用 http+nacos://order-service 寻址。
Lolitacoding.Nacos.AspNetCore ASP.NET Core 应用启动时注册实例、停止时注销。
Lolitacoding.Aspire.Hosting.Nacos AppHost 里编排一个 Nacos 服务端容器。
Lolitacoding.Aspire.Nacos 客户端侧 AddNacosClient(...)，绑定注入的连接串。

05 — 开始

五分钟，从空项目到连上

  1. 装包

    预览版发布后可直接安装；在那之前从源码构建。

    dotnet add package Lolitacoding.Nacos --prerelease

  2. 连上

    构造不连接，ConnectAsync 才建立连接；也可以交给 DI 托管。

    NacosClient client = NacosClient.Create(new NacosOptions
{
    ServerAddresses = ["http://127.0.0.1:8848"],
});
await client.ConnectAsync();

  3. 接进宿主

    用扩展包把连接交给容器，而不是自己管生命周期。

    builder.Services.AddNacos(options =>
{
    options.ServerAddresses = ["http://127.0.0.1:8848"];
    options.Namespace = "public";
});

builder.AddNacosConfiguration(options =>
{
    options.DataIds = ["appsettings.json"];
    options.Optional = true;
});
